# BUG 端到端流程

## 1. 提交

必填：标题、描述、实际结果。建议：复现步骤、期望结果、环境、版本、错误日志、严重度、是否生产问题、指定项目。

## 2. 分析

`AiAnalysisPort` 输出结构化报告：问题类型、严重度、影响范围、疑似模块、复现可能性、缺失信息。信息不足时进入人工补充。

## 3. 项目匹配

用户指定优先；否则按服务名、日志包名、代码路径、别名与历史相似 BUG 评分：

| 置信度 | 处理 |
|---|---|
| `>= 0.80` | 自动匹配 |
| `0.60 ~ 0.80` | `WAITING_PROJECT_CONFIRM` |
| `< 0.60` | 人工分派 |

## 4. 拆分与执行

- 并行：代码分析、根因分析、测试分析
- 串行：开发 → 测试 → 审查
- 同一工作区只允许一个写入型 Agent
- 每个子任务声明输入、输出、允许路径与验收标准

## 5. 交付

首期只生成可审查的变更报告：差异、测试结果、审查意见、修复轮次。推送、dcommit、部署均需显式审批。
